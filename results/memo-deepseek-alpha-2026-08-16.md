# DeepSeek Harness Alpha Memo — transferable patterns for the Lily companion actor

Date: 2026-08-16 (Spike 5 synthesis; six reader agents + one synthesizer)
Source: `/home/vruizes/deepseek-harness` — @deepseek-ai/dsh-root rc.5, the DeepSeek coding-agent monorepo (deepseek-v4-flash's native harness)

## Why

Lily's actor **is** deepseek-v4-flash, called through an OpenAI-compatible proxy (opencode). This monorepo is the agent the model was fine-tuned inside: its request layout, system-prompt shape, thinking wire conventions, tool discipline, sampling omissions, and compaction mechanics are the model's *native usage pattern* — the defaults our companion does not currently match. Almost everything here is a serving/context mechanic, not coding logic, so the transfer surface to a companion is unusually large. The single most important discovery: **the harness never uses `cache_control` or any cache flag — cache hits are engineered purely by keeping every request a byte-identical extension of the last one**, and a key-gated e2e test enforces that against the live API. That discipline survives any gateway.

## Provenance note

Patterns only — zero source code copied. The harness is third-party licensed (MIT, vendored); every row below is a reimplementable *idea* cited to a real `file:line` in the vendored tree. Gateway flags assume Lily's opencode OpenAI-compatible proxy: *gateway-compatible* = pure client-side structure; *needs-native* = requires DeepSeek's native API fields to pass through; *verify* = depends on passthrough, probe once before relying on it.

## Top 3 to act on now

1. **Adopt the static-prefix / volatile-tail + frozen-header cache discipline (rows 1–3).** Freeze Lily's persona + tool list as a byte-identical per-conversation epoch header, send all mutable state as a trailing user message with "supersedes" language, and add a cached-tokens>0 assertion on later steps of real sessions. This is the entire cache story of the model's own harness, needs no vendor flag (survives the opencode proxy), and is directly testable via usage fields.
2. **Harden the serializer against v4-flash's reasoning-only turns (row 6).** Guarantee assistant `content` is always a string — `""` never null — and replay `reasoning_content` only on turns that carried tool calls. This model answers entirely in the reasoning channel (a documented, brick-the-session failure mode in the harness); the rule must live in the companion's serializer, not in a prompt.
3. **Adopt purpose-tagged cheap-call policy for all side-work (rows 12 + 9).** Tag session-title/memory-write/briefing calls with thinking off, JSON-framed input, a strict one-line output contract, small maxTokens, and log-before-dispatch. Matches the harness's own small-model pattern; drops latency/tokens on the highest-frequency calls and is fully gateway-compatible (omission of thinking fields).

## Not transferable / watch-out

- **Coding-agent-only (do not port):** terminal/PTY guidance bands, sandbox policy-denial text for bash, `run_code` nested transports, goal/plan-mode policy sections, workspace-instruction byte-budget machinery, tool-catalog generation from live plugin boots. Used here only for framing mechanics (bands, slots, sanitization), never content.
- **Needs-native-API / probe before relying (row 6, 9, 14):** `thinking:{type}` toggle, `reasoning_effort` levels, and `reasoning_content` passback through the opencode proxy are unverified — a probe must confirm they survive the gateway. Same for `usage.prompt_tokens_details.cached_tokens` and `completion_tokens_details.reasoning_tokens`. Design all cache/effort observability to be optional; never hard-fail when the gateway strips them.
- **Cache measurement ≠ cache reality behind a proxy:** prefix caching is server-side on input bytes, so ordering discipline transfers, but "cacheReadTokens > 0" can only be asserted once usage details pass through; treat it as best-effort until then.
- **"low"/"medium" reasoning effort levels are not honored** ('high'/'max' only; low/medium map to high server-side, types.ts:20-21) — don't offer client knobs the API silently collapses.
- **Never serialize explicit nulls/zeros:** the harness omits temperature/max_tokens/stop when unset so provider defaults apply; there is NO temperature default anywhere in the harness — the omission philosophy is the default (serialize.ts:183-185, adapter.ts:91-93).
- **Thinking is not a lifecycle stage:** the harness has no "think phase" — reasoning is a block type inside one streamed step (agent-lifecycle.md). Don't design Lily's loop around an explicit analysis stage; design around a per-turn channel toggle.
